# The research problem

Replace this placeholder before starting substantive work. Keep definitions and
scope precise enough that two researchers can test the same statement.

## Exact question

What must be proved, refuted, decided, constructed, or measured?

## Input and semantics

Define the input objects, constructors, notation, domains, and boundary cases.
State the quantifiers. If values can be finite, regular, infinite, partial, or
unbounded, say which cases are included.

## Intended conclusion

State the strongest desired result and the weakest useful result. Explain what a
restricted theorem, counterexample, lower bound, or negative result would add to
the general problem.

## Existing knowledge

Link prior results, exact theorem identifiers, and source files. Map imported
hypotheses to the objects in this problem. Leave any unproved transfer as an
explicit obligation.

## Candidate routes

For each route, name its approach ID after creation, core construction, main
assumption, likely failure mode, and the observation that would change the
route. Keep decidability, hardness, undecidability, and structural routes live
until evidence narrows them.

## First investigation

Choose the smallest discriminating question. Give the input family or proof
obligation, bounds, independent checker, acceptable outcomes, and the next move
for each outcome. A bounded negative result is `UNKNOWN` unless completeness is
proved.
